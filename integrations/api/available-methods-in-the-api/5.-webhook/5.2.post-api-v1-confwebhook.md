# ✔️ 5.2.POST/api/v1/confwebhook

## Request

**Guidelines:**

* When the required field is marked as "Yes" = Always required
* When the required field is marked as "No" = Optional information
* When the required field is marked as "Maybe" = In some cases, it will be required. To know these cases, refer to the description of the topic, according to the reference number of the line in the table.

## Validations

### Specific Validations

> **nome**&#x20;
>
> **Description:** Parameter indicating the name of the Webhook.&#x20;
>
> **Format:** String&#x20;
>
> **Required:** <mark style="color:red;">Yes</mark>&#x20;
>
> **Validation:**&#x20;
>
> a- The system validates the requirement and size of the String, allowing up to 150 characters for the **name** parameter.&#x20;
>
> b- The system does not allow registering a Webhook with the same name in the account in question.

> **status**&#x20;
>
> **Description:** Parameter indicating the status of the Webhook.&#x20;
>
> **Format:** Tinyint - 1 = Active, 2 = Inactive&#x20;
>
> **Required:** <mark style="color:red;">Yes</mark>&#x20;
>
> **Validation:**&#x20;
>
> a- Only values equal to 1 or 2 are allowed.

> **urlPublicar**
>
> **Description:** Parameter indicating the URL that will be called by the Webhook.
>
> **Format:** String
>
> **Required:** <mark style="color:red;">Yes</mark>
>
> **Validation:**
>
> a- If a URL with spaces is provided, the system removes those spaces.

> **aguardarRetorno**&#x20;
>
> **Description:** Parameter indicating whether the Webhook should wait for a response or not.&#x20;
>
> **Format:** Bit - 1 = true or 0 = false&#x20;
>
> **Required:** <mark style="color:blue;">No</mark>&#x20;
>
> **Validation:**&#x20;
>
> a- When the information is **not sent or sent as null**, the system considers it as **0 = false**.

**usuarios**&#x20;

> This part of the JSON is optional, and the user can specify one or more user IDs to restrict the execution of the Webhook. That is, the Webhook will only execute if the document signing process was created by the user specified in this parameter.&#x20;
>
> **Description:** Parameter indicating one or more user IDs of the account.&#x20;
>
> **Format:** Guid&#x20;
>
> **Required:** <mark style="color:blue;">No</mark>&#x20;
>
> **Validation:**
>
> a- When IDs are sent in this parameter, the system validates whether they belong to the account and checks the user's status.
>
> If a list of users is provided, the system **saves only those belonging to the account with active status** and disregards the others.
>
> If none of the provided users **belong to the account**, the system displays the message: _User(s) not found._
>
> If the provided users belong to the account but have **a status other than active**, the system displays the message: _Only users with active status are allowed._
>
> When a list of users is provided, only those with active status are saved, and the others are disregarded.

**grupos**&#x20;

> This part of the JSON is **optional**, and the user can specify one or more group IDs to restrict the execution of the Webhook. That is, the Webhook will only execute if the document signing process was created by a user in the specified group.&#x20;
>
> Description: Parameter indicating one or more group IDs of the account.&#x20;
>
> **Format:** Guid&#x20;
>
> **Required:** <mark style="color:blue;">No</mark>&#x20;
>
> **Validation:**&#x20;
>
> a- When IDs are sent in this parameter, the system validates if the group belongs to the account. If a list of groups is provided, the system **saves only those that belong to the account** and disregards the others.&#x20;
>
> If all the groups provided do **not belong to the account**, the system displays the message: "Group(s) not found."

**pastas**

> This part of the JSON is **optional**, and the user can specify one or more folder IDs to restrict the execution of the Webhook. That is, the Webhook will only execute if the document signing process was created in one of the folders specified in this parameter.&#x20;
>
> **Description:** Parameter indicating one or more folder IDs.&#x20;
>
> **Format:** Guid&#x20;
>
> **Required:** <mark style="color:blue;">No</mark>&#x20;
>
> **Validation:**&#x20;
>
> a- When IDs are sent in this parameter, the system validates if the **folder** belongs to the account.&#x20;
>
> If a list of folders is provided, the system **saves only those belonging to the account** and disregards the others.&#x20;
>
> If **all** the folders provided do **not belong to the account**, the system displays the message: "Folder(s) not found."

**gatilhos**

> **Description:** Parameter indicating the trigger that will activate the Webhook.&#x20;
>
> **Format:** Tinyint&#x20;
>
> **Required:** Yes&#x20;
>
> **Validation:**&#x20;
>
> a- It is mandatory to provide at least one trigger for the Webhook.&#x20;
>
> b- The system validates the provided trigger, allowing one of the options below.&#x20;
>
> > 1- Process sent&#x20;
> >
> > 2- Process with sending failure&#x20;
> >
> > 3- Process signed by any signatory&#x20;
> >
> > 4- Process rejected by any signatory&#x20;
> >
> > 5- Process canceled by the sender&#x20;
> >
> > 6- Process expired&#x20;
> >
> > 7- Process resent&#x20;
> >
> > 8- Process signed/completed by all signatories

**dadosRetorno**

> This part of the JSON is optional, and the user can specify the return data for the Webhook.&#x20;
>
> If these parameters are not sent or are sent as null, the Webhook will return only the following data to the URL provided in the urlPublicar parameter:
>
> ```
> {
>     "evento": "string",
>     "idProcesso": "guid",
>     "idConta": "guid",
>     "idWebhook": "guid",
>     "dataHoraAtual": "dd/mm/aaaa hh:mm:ss"
> }
> ```
>
> > **processo**
> >
> > > **Description:** Parameter indicating whether the Webhook should return the data of the signing process.&#x20;
> > >
> > > **Format:** Bit - 1 = true or 0 = False&#x20;
> > >
> > > **Required:** <mark style="color:blue;">No</mark>&#x20;
> > >
> > > **Validation:**&#x20;
> > >
> > > a. When the information is **not sent or is sent as null**, the system considers it as **0 = false.**
> >
> > **signatarios**
> >
> > > **Description:** Parameter indicating whether the Webhook should return the signatories' data of the signing process.&#x20;
> > >
> > > **Format:** Bit - 1 = true or 0 = False&#x20;
> > >
> > > **Required:** <mark style="color:blue;">No</mark>&#x20;
> > >
> > > **Validation:**&#x20;
> > >
> > > a. When the information is **not sent or is sent as null**, the system considers it as **0 = false.**
> >
> > **documentos**
> >
> > > **Description:** Parameter indicating whether the Webhook should return the documents of the signing process.&#x20;
> > >
> > > **Format:** Bit - 1 = true or 0 = False&#x20;
> > >
> > > **Required:** <mark style="color:blue;">No</mark>&#x20;
> > >
> > > **Validation:**&#x20;
> > >
> > > a. When the information is **not sent or is sent as null**, the system considers it as **0 = false.**
> >
> > **documentosTipo**
> >
> > > **Description:** Parameter indicating the format of the documents that will be returned by the Webhook.&#x20;
> > >
> > > **Format:** Byte - 1 = Base64, 2 = Download link&#x20;
> > >
> > > **Required:** <mark style="color:red;">Yes, when the documentos parameter equals 1</mark>&#x20;
> > >
> > > **Validation:**&#x20;
> > >
> > > a- Only values equal to 1 or 2 are allowed.&#x20;
> > >
> > > b- The **documentosTipo** parameter is mandatory when the **documentos parameter equals 1** (true).
> >
> > **linkDocCompartilhado**
> >
> > > **Description:** Parameter indicating whether the Webhook should return the shared link (QR Code link) of the signing process.&#x20;
> > >
> > > **Format:** Bit - 1 = true or 0 = False&#x20;
> > >
> > > **Required:** <mark style="color:blue;">No</mark>&#x20;
> > >
> > > **Validation:**&#x20;
> > >
> > > a. When the information is **not sent or is sent as null**, the system considers it as **0 = false.**
> >
> > **registrosAssinatura**
> >
> > > **Description:** Parameter indicating whether the Webhook should return the signing records of the signing process.&#x20;
> > >
> > > **Format:** Bit - 1 = true or 0 = False&#x20;
> > >
> > > **Required:** <mark style="color:blue;">No</mark>&#x20;
> > >
> > > **Validation:**&#x20;
> > >
> > > a. When the information is **not sent or is sent as null**, the system considers it as **0 = false.**
> >
> > **registrosAssinaturaTipo**
> >
> > > **Description:** Parameter indicating the format of the signing records that will be returned by the Webhook.&#x20;
> > >
> > > **Format:** Byte - 1 = Base64, 2 = Download link&#x20;
> > >
> > > **Required:** <mark style="color:red;">Yes, when the registrosAssinatura parameter equals 1</mark>&#x20;
> > >
> > > **Validation:**&#x20;
> > >
> > > a. Only values equal to 1 or 2 are allowed. b. The **registrosAssinaturaTipo** parameter is mandatory when the **registrosAssinatura** parameter **equals 1** (true).

### General Validations

**Authentication**

1- The user must provide the **AppKey** and **SubscriptionKe**y (SubscriptionKey1 or SubscriptionKey2) of the account that is registering the Webhook configuration.

2- Only accounts **with Active status** can register a Webhook configuration via the ArqSign integration. The account must be identified through the AppKey.

## Validation Response

### Error: 400 - Bad Request

This error is returned when the request cannot be interpreted and/or the server attempts to process the request, but a parameter in the request is invalid, such as a resource formatted incorrectly or a missing data attempt. Information about the request is provided in the response body, including an error code and an error message.

**a- Mandatory Item:** This message is shown in singular or plural when one or more mandatory items were not sent in the API call.

> **Message:** The listed item(s) is/are mandatory: “names of items separated by commas”.

**b- Incorrect Format:** This message is shown in singular or plural when one or more items were sent with an incorrect format.

> **Message:** The listed item(s) have an incorrect format: “names of items separated by commas”.

**c- Nonexistent Ids:** This message is shown in singular or plural when one or more Ids sent do not exist.

> **Message:** The listed Id(s) do not exist: “names of items that are table Ids, separated by commas”.

**d- Incorrect or Nonexistent Parameter:** This message is shown when a call is made with a misspelled parameter or when information is sent that does not exist in the method.

> **Message:** Some parameter is incorrect or nonexistent.

### Error: 401 – Unauthorized

This error is returned when:

* The ArqSign API authentication key is incorrect or was not provided correctly.
* The account has a status other than Active.

### Error: 404 - Not Found

This error is returned when the requested resource or endpoint cannot be found.

### Error: 500 - Server Error

This error is returned when:

* An internal server error occurs.
* A failure occurs in the ArqSign platform.
* The parameter format is incorrect.
* The JSON format is incorrect.

## Success Response

Upon successful registration of the Webhook configuration, the system returns:

* Webhook Id
* Webhook Name
* HMAC Key
* Code 200 – OK

### Return - Example Body Response

```
{
    "id": "guid",
    "nome": "string",
    "chaveHMAC": "string"
}
```

1. **id**

The system returns the id of the created Webhook configuration.

2. **nome**

The system returns the name of the created Webhook configuration.

3. **chaveHMAC**

The system returns the HMAC key generated for the Webhook configuration.
