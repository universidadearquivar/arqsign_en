# ✔️ 1.1. POST/api/v2/processo/enviar-documento-para-assinar

The purpose of this method is to allow clients, via API, to send processes containing one or more documents for signature.

Unlike the ArqSign application, which enables grouping files within a process, this service treats multiple documents **in a process as a collection of files**. These files will not be grouped into a single document. In other words, file grouping is not possible through the document signature process submission service.

The user must provide the process details and the participants' information for the signing process.

## Authentication and Permissions

1. To authenticate with the ArqSign API, the user must provide a valid AppKey associated with the account sending the documents for signatures.
2. Only accounts with **Active status** and **ArqSign Integration permissions** can submit processes via the ArqSign integration.
3. The account must have sufficient credits for Submissions, SMS, and/or WhatsApp, depending on the requirements.
4. If the account lacks credits, the system will return the message: _"Insufficient credits for Submissions, WhatsApp, or SMS."_

## Request: Parameters

**Guidelines:**

When the "Required" field is marked as "Yes" = Always required.

When the "Required" field is marked as "No" = Optional information.

When the "Required" field is marked as "Maybe" = Required in certain cases. Refer to the topic description according to the row reference number in the table.

When the "Required" field is marked as "No" = Optional information.

## Description of JSON Parameters

### idResponsavel

**Mandatory** parameter specifying the ID of the process owner. This information will be considered the owner responsible for the registration and the process, i.e., the "sender" of the process. Thus, if the specified user logs into the application, they will see all documents in the "Enviados" menu.

You must provide the ID of an active user belonging to the account.

### nomeProcesso

Mandatory parameter specifying the name of the process, allowing up to 250 characters.

### idPasta

Mandatory parameter specifying the folder ID of the process. You must provide the ID of a folder belonging to the account.

### configuracoesAvancada

In this section of the JSON, the user can send advanced settings for the process, including expiration time, expiration warning, frequency of this warning, QRCode generation, and document reading requirement for the process.

Advanced settings are **optional**. **If not sent** or sent as null, the system **saves the process with the account's default settings**.

### tempoExpiracaoDocumentoDias

**Optional** parameter specifying the time the process will be available for signature until all signers sign and the process is completed.\
Allowed values range from {1} to {999}.

If this parameter is not sent, sent as null, or set to 0, the system uses the account's default settings.

### avisoAntesExpiracaoDocumentoDias

**Optional** parameter specifying the time for the application to start warning before the document expires.\
Allowed values range from {1} to {99}.

If this parameter is not sent, sent as null, or set to 0, the system uses the account's default settings.

### frequenciaLembretesDias

**Optional** parameter specifying the frequency of signature reminders.\
Allowed values range from {1} to {999}.

If this parameter is not sent, sent as null, or set to 0, the system uses the account's default settings.

### gerarQrCode

**Optional** parameter specifying whether to generate the QRCode for the signed document upon process completion.\
If the process includes more than one document for signature, the QRCode will be generated per document. Each document will have its QRCode and signature page.

Allowed values: 1 = true or 0 = false.

If this parameter is not sent, sent as null, or set to 0, the system uses the account's default settings.

### obrigarLeitura

**Optional** parameter specifying whether document reading is mandatory before signing.\
If the process includes more than one document to sign, this information will determine whether the signer is required to click on each document before the "Assinar" button is enabled.\
If the process has only one file to sign, this information is not necessary for the signing process.

Allowed values: 1 = true or 0 = false.

If this parameter is not sent, sent as null, or set to 0, the system uses the account's default settings.

### renovacaoMeses

**Optional** parameter specifying the renewal period, in months, for the process in question.

### mensagemPadrao

**Optional** parameter specifying the default message to be sent to all recipients designated as signers of the process.\
If the **“mensagemPadrao” data collection is not sent**, the system sends notifications with default values:\
**Title** = ArqSign: \[Document name provided in the "nome" parameter]\
**Text** = You have received the document(s): \[Document name provided in the "nome" parameter] for signatures.

**Title**\
**Optional** parameter specifying the title of the message to be sent to the signers.

**text**\
**Optional** parameter specifying the text of the message to be sent to the signers.

### usarOrdemAssinatura

Mandatory parameter indicating whether or not the order of signature will be used for the signers.\
Allowed values: 1 = true or 0 = false.

a. When the **usarOrdemAssinatura** parameter is sent as false, the system disregards the value specified in the **ordemAssinatura** parameter for all recipients with the "Assinar Online" action and sends the process to all recipients, treating them as order 1.

b. When the **usarOrdemAssinatura** parameter is sent as true, the system validates the **ordemAssinatura** parameter for all recipients with the "Assinar Online" action. In this case, the **ordemAssinatura** parameter for the recipients cannot be zero or null.

If the process has a signing order, the system sends the process only to recipients with order 1.

### usarPosicaoAssinaturaAutomatica

Mandatory parameter to indicate whether the process will include a signature page at the end of each file. On this page, the application automatically selects where each signature will be positioned.\
Allowed values: 1 = true or 0 = false.

a. When the **usarPosicaoAssinaturaAutomatica** parameter is **true**, the application **will include a page at the end of each file with the signature position for each recipient with the "Sign Online" action**, based on the type of person for each signer as described below:

* For signers with the parameter **assinarComo = 1** (Pessoa física), the application will include a page at the end of the file with the automatic definition of the signature position for a "**Pessoa Física**" (PF).
* For signers with the parameter **assinarComo = 2** (Pessoa jurídica), the application will include a page at the end of the file with the automatic definition of the signature position for a "**Pessoa Jurídica**" (PJ).
* For signers with the parameter **assinarComo = 3** (Pessoa física e jurídica), the application will include a page at the end of the file with the automatic definition of two signature positions: one for "Pessoa Física" (PF) and one for "Pessoa Jurídica" (PJ).

When the **usarPosicaoAssinaturaAutomatica** parameter is **true**, it is not necessary to send the **definirPosicaoAssinaturaManual** parameters. However, if the JSON includes the **definirPosicaoAssinaturaManual** parameter for any signer, this information will be ignored in this case.

b. When the **usarPosicaoAssinaturaAutomatica** parameter is sent as **false**, it means the signature positions **for each signer** must be provided manually **for each file in the process**. In this case, the **definirPosicaoAssinaturaManual** parameter data must be included.

{% hint style="danger" %}
<mark style="color:red;">**Important:**</mark> <mark style="color:red;"></mark><mark style="color:red;">In the JSON, all recipients with the action of signing online must have the visual representation positioning set automatically by the application, or the positioning for all must be manually provided in the JSON. It is not allowed to have some recipients with automatic positioning and others without automatic positioning within the same process.</mark>
{% endhint %}

### Recipients

**idTipoAcao**

**Mandatory** parameter defining the recipient's action regarding the document. Currently, there are two options: **1 - Sign Online or 2 - Receive a copy**.\
It is allowed to inform 1 - Sign Online or 2 - Receive a copy.

a. It is mandatory to include at least one recipient with the action "**Sign Online**" in the signing process.

**ordemAssinatura**

Parameter that defines the signing order of the respective recipient.

a. When the parameter "**usarOrdemDeAssinatura**" is sent as **True = 1** and the recipient in question has the parameter **idTipoAcao = 1 (Sign Online)**, this information is mandatory.

**ordemAssinatura** should not be sent in the JSON or will be disregarded when:

* **idTipoAcao = 2 (Receive a copy).**
* **usarOrdemDeAssinatura** **= 0 (phase)** and recipients have i**dTipoAcao = 1 (Sign Online).**

b. The application does **not allow the same recipient in the same signing order.** To verify if the recipient is the same, the email or phone number used as the delivery method for the document is checked for duplication within the same signing order.

**nome**

**Mandatory** parameter specifying the recipient's name who will sign the document or receive a copy.

a. The system validates the mandatory field and the length of the recipient's name.

**email**

Parameter providing the email address where the recipient will receive the document.

**Format:** Varchar(150)\
**Required: Either Email or Phone number is mandatory.**

**Validation:**

a. The system checks the **mandatory** requirement for either email or phone number.\
If neither email nor phone number is provided, the application validates the data and displays the message: The parameter **email or phone number** is mandatory.

b. Only **valid email** addresses are allowed.

c. Only one delivery method **is permitted: either email or phone number.**\
If both fields are provided, the system returns the message: It is only possible to send the process to an email or a phone number. Please choose one delivery method.

**telefone**

Parameter providing the phone number where the recipient will receive the document. Providing the phone number indicates that the document will be sent via **WhatsApp**.

a. The system checks the **mandatory** requirement for either **email or phone number**.\
If neither email nor phone number is provided, the application validates the data and displays the message: **The parameter email or phone number is mandatory.**

b. The system **validates** the provided phone number.

c. Only one delivery method **is permitted: either email or phone number.**\
If both fields are provided, the system returns the message: It is only possible to send the process to an email or a phone number. Please choose one delivery method.

d. It is only possible to send the process via WhatsApp when the recipient meets one of the following requirements:

1. Will electronically sign the document **(idTipoAcao = 1 (Sign Online)** and **idTipoAssinatura = 1 (Electronic Signature)).**
2. Will receive a copy **(idTipoAcao = 2 (Receive a copy)).**

### assinarOnline

This part of the JSON should only be sent for recipients with **idTipoAcao = 1 (Sign Online).** If sent for a recipient with **idTipoAcao = 2 (Receive a copy)**, this data will be ignored.

**assinarComo**

**Mandatory** parameter indicating whether the signer with **idTipoAcao = 1 (Sign Online)** will sign as an individual, legal entity, or both.\
It is allowed to inform:\
1 = Individual\
2 = Legal Entity\
3 = Individual and Legal Entity

**papelPessoaFisica**

Optional parameter to send the signer's roles regarding the individual signature they will perform.

a. The **papelPessoaFisica** parameter is optional, but when provided, the system checks if the account has the signer's role specified.\
The user may either send **null** or omit this parameter in the JSON.

If **papelPessoaFisica** is sent for a signer with **assinarComo = 2 (Legal Entity)**, this information is disregarded.

**papelPessoaJurídica**

Optional parameter to send the signer's roles regarding the legal entity signature they will perform.

a. The **papelPessoaJuridica** parameter is optional, but when provided, the system checks if the account has the signer's role specified.\
The user may either send **null** or omit this parameter in the JSON.

If **papelPessoaJuridica** is sent for a signer with **assinarComo = 1 (Individual)**, this information is disregarded.

**seguranca**

This part of the JSON is optional and should only be sent if there is a need to require the signer to input a security code to begin the signing process.

**codigoSeguranca**

Security code to be required from the signer who will sign the document. This information must be numeric with 4 characters.

**idMeioEnvio**

Parameter to specify how the security code will be sent to the signer in question.\
This parameter is only required if **codigoSeguranca** is sent, and only the following values are allowed:\
1 = SMS (Only in Brazil),\
2 = WhatsApp,\
3 = Email,\
4 = Do not send.

The system ignores this parameter if **codigoSeguranca = null.**

**codigoSegurancaEmail**

Email where the signer should receive the security code defined in the **codigoSeguranca** parameter.

a. The **codigoSegurancaEmail** parameter is mandatory when the **idMeioEnvio** parameter is set to 3.

b. The application validates whether the information provided is a valid email.

If this parameter is sent when **idMeioEnvio** ≠ 3, the system ignores the information.

The system ignores this parameter if **codigoSeguranca = null.**

**codigoSegurancaTelefone**

Phone number where the signer should receive the security code defined in the **codigoSeguranca** parameter.

a. The **codigoSegurancaTelefone** parameter is mandatory when the **idMeioEnvio** parameter is set to 1 or 2.

When **idMeioEnvio = 1 (SMS)**, only Brazilian phone numbers will be accepted.

The system validates the phone number provided.

If this parameter is sent when **idMeioEnvio = 3 or 4**, the system ignores the information.

The system ignores this parameter if **codigoSeguranca = null.**

**reenviarCodigo**

Information that defines whether the signer can resend the security code to their phone via SMS or WhatsApp as defined in the **idMeioEnvio** parameter.

If the **reenviarCodigo** parameter is not provided in the JSON, the service considers it as **false**.

It is allowed to inform:\
1 = True\
0 = False

a. This parameter is only mandatory when the security code is sent via SMS or WhatsApp.

If this parameter is sent when **idMeioEnvio = 3 or 4**, it is disregarded.

**mensagemPersonalizada**

This part of the JSON is optional and should only be sent if a custom message needs to be sent to the signer in question. If the message title is provided, the text must also be sent, and vice versa.

**titulo**

Title of the custom message to be sent to the signer in question. Recipients with a custom message will not receive the **mensagemPadrao**.

a. The **mensagemPersonalizada** parameter is not mandatory, but when the "title" is provided, the application must require the text and vice versa.

**texto**

Text of the custom message to be sent to the signer in question. Recipients with a custom message will not receive the **mensagemPadrao**.

a. The **mensagemPersonalizada** parameter is not mandatory, but when the "title" is provided, the application must require the text and vice versa.

**anexos**

This part of the JSON is **optional** and should only be sent if the signer needs to upload a file at the time of signing. If any of the following parameters are sent, all three must be provided:**anexoDocumentoNome, anexoObrigatorio, anexoExibirTodosDestinatarios.**

1. **anexoDocumentoNome**

Name of the file that will be requested from the signer at the time of signing the documents.

It is allowed to inform up to 75 characters.

2. **anexoObrigatorio**

Information to require the signer to upload the file at the time of signing the document.

It is allowed to inform:\
1 = true\
0 = false

3. **anexoExibirTodosDestinatarios**

Information to display the file uploaded by the signer to all other recipients, whether they are required to sign or not. If the uploaded file requires confidentiality, this information should be sent as false.

It is allowed to inform:\
1 = true\
0 = false

**definirPosicaoAssinaturaManual**

This part of the JSON is mandatory only if the parameter **usarPosicaoAssinaturaAutomatica** is set to false.\
When **usarPosicaoAssinaturaAutomatica** is sent as false, the JSON must include the manual position of the signature for all recipients with the "Sign Online" action in each file of the process. This means it is mandatory to manually define the signature position (**definirPosicaoAssinaturaManual**) for each recipient in each document (**documentoDeOrdem**) according to the value set in the **assinarComo** parameter (1 = Individual, 2 = Legal Entity, or 3 = Individual and Legal Entity).

When **usarPosicaoAssinaturaAutomatica** is sent as true, the manual signature position data for all signers will be disregarded. In this case, a page will be added to the end of each document showing the signature position of each recipient with the "Sign Online" action.

The system validates that the manual signature position is within the limits of the page specified.\
The system validates the manual representations sent for recipients, not allowing the same manual representation for the same type of signature within the same document (**documentoDeOrdem**).

**documentoDeOrdem**

When the signing **process** being sent in the JSON contains more than one file for signing, this field will be used to identify the file to which the signature positioning described in the following parameters refers.

If the signing process contains only one file to be signed, this field becomes unnecessary and will be disregarded when sent.\
a. This parameter is mandatory whenever the process contains more than one file to be signed.

b. The system validates whether the document in the specified “**documentoDeOrdem**” exists.

**pessoaFisica**

The parameters below will indicate the signature positioning for the individual signatory in the file identified in "**documentoDeOrdem**" and will be mandatory when the parameters "**usarPosicaoAssinaturaAutomatica = false**" and "**assinarComo = 1 (PF)**" or "**3 (PF and PJ)**" are set.

When "**assinarComo = 2 (PJ)**", these data will be disregarded.\
The parameters below will indicate the signature positioning for the individual signatory in the file identified in "**documentoDeOrdem**".

1. **pagina**\
   This information is the page of the file where the signature position will be placed. It is **mandatory** when "**usarPosicaoAssinaturaAutomatica = false**" and "**assinarComo = 1 (PF)**" or "**3 (PF and PJ)**".

**a.** This information cannot be zero or null.

**b.** The application validates whether the specified page exists in the file.

2. **altura**\
   Height in millimeters of the box where the signature will be applied. It is **mandatory** when "**usarPosicaoAssinaturaAutomatica = false**" and "**assinarComo = 1 (PF)**" or "**3 (PF and PJ)**".

Decimal values are allowed.\
**a.** This information cannot be null.

3. **largura**\
   Width in millimeters of the box where the signature will be applied. It is **mandatory** when "**usarPosicaoAssinaturaAutomatica = false**" and "**assinarComo = 1 (PF)**" or "**3 (PF and PJ)**".

Decimal values are allowed.\
a. This information cannot be null.

4. **posicaoX**\
   **Description:** Position in millimeters from the left edge of the page to the left edge of the signature box.

It is **mandatory** when "**usarPosicaoAssinaturaAutomatica = false**" and "**assinarComo = 1 (PF)**" or "**3 (PF and PJ)**".\
Decimal values are allowed.\
**a.** This information cannot be null.

5. **posicaoY**\
   **Description:** Position in millimeters from the top edge of the page to the top edge of the signature box.

It is mandatory when "**usarPosicaoAssinaturaAutomatica = false**" and "**assinarComo = 1 (PF)**" or "**3 (PF and PJ)**".\
Decimal values are allowed.\
a. This information cannot be null.

When "**assinarComo = 1 (PF)**", these data will be disregarded.

**idTipoAssinatura**

Definition of the type of signature that will be required from the signatory, which can be: **1 = Electronic Signature, 3 = ICP Brazil Digital Certificate, 4 = Other Digital Certificate.**

**a.** This information is mandatory for all signatories with the parameter "idTipoAcao = 1 (Sign Online)".\
**b.** The application only allows the values 1, 3, or 4.

**assinaturaEletronica**

This part of the JSON is only mandatory for signatories with "**idTipoAssinatura = 1 (Electronic Signature)**".

* **obrigarSignatarioInformarNome**

Information to require the signatory to provide their name. Allowed values: 1 = True or 0 = False

**a.** This information is mandatory for all signatories with "idTipoAssinatura = 1 (Electronic Signature)".

* **obrigarSignatarioInformarNumeroDocumento**\
  Information to require the signatory to provide their document number.                                       Allowed values: 1 = True or 0 = False

**a.** This information is mandatory for all signatories with "idTipoAssinatura = 1 (Electronic Signature)".

* **tipoDocumentoAInformar**\
  Type of document that the signatory must provide at the time of signing, allowing the following values: **1 = CPF, 2 = CNH, 3 = RH or 4 = Other.**

**a.** This information is mandatory for all signatories with "idTipoAssinatura = 1 (Electronic Signature)".\
**b.** When provided, the system validates the "**tipoDocumentoAInformar**" parameter, allowing only the values: **1 = CPF, 2 = CNH, 3 = RH, or 4 = Other.**

**configuracaoDocumentoOutro**\
This part of the JSON is only **mandatory** when "**tipoDocumentoAInformar**" is equal to **4 = Other**. This part allows you to define the parameters for the document that will be requested from the signatory at the time of signing.

**nomeDocumento**\
Name of the document that will be displayed to the signatory during the document signing process.

Allowed values: up to 50 characters.

**formatoDadosDocumento**\
Data format required for the document field, allowing the value 1 = Text or 2 = Numeric.

**qtdeCaracteresDocumento**\
Number of characters required in the document field.

**obrigarSignatarioInformarNomeEmpresa**\
Information for the application to require the signer to provide the company name (legal entity).

It is allowed to inform 1 = True or 0 = False.

**a.** This information is mandatory for signers when the parameters idTipoAssinatura = 1 (Electronic Signature) and assinarComo is equal to 2 = Legal Entity or 3 = Natural and Legal Entity.

**obrigarSignatarioInformarNumeroDocumentoEmpresa**\
Information for the application to require the signer to provide the company document (legal entity).

It is allowed to inform 1 = True or 0 = False.

**a.** This information is mandatory for signers when the parameters idTipoAssinatura = 1 (Electronic Signature) and assinarComo is equal to 2 = Legal Entity or 3 = Natural and Legal Entity.

**tipoDocumentoEmpresaAInformar**\
Type of document that the signer must provide for the company.

It is allowed to inform 4 = Other or 5 = CNPJ.

**a.** This information is mandatory for signers when the parameters idTipoAssinatura = 1 (Electronic Signature) and assinarComo is equal to 2 = Legal Entity or 3 = Natural and Legal Entity.

**b.** When informed, the system will validate the parameter **tipoDocumentoEmpresaAInformar** allowing only the values: 4 = Other or 5 = CNPJ.

**configuracaoDocumentoEmpresaOutro**\
This part of the JSON is only **mandatory when tipoDocumentoEmpresaAInformar is equal to 4 = Other.**

In this part, it is possible to define the parameters of the document that will be requested from the signer at the time of signing.

1. **nomeDocumento**\
   Name of the document that will be displayed to the signer as the company document, allowing up to 50 characters.

**a.** This information is mandatory for all signers with tipoDocumentoEmpresaAInformar = 4 (Other).

2. **formatoDadosDocumento**\
   Format of the data that will be required in the company document field, allowing 1 = Text or 2 = Numeric.

**a.** This information is mandatory for all signers with tipoDocumentoEmpresaAInformar = 4 (Other).

3. **qtdeCaracteresDocumento**\
   Number of characters that will be required in the document field.

**a.** This information is mandatory for all signers with tipoDocumentoEmpresaAInformar = 4 (Other).

### documentos

**a.** This part of the JSON **is mandatory, requiring at least one file to be sent.**

**b.** It is allowed to send up to 25 files per process.

**c.** The total size of these files cannot exceed **100MB.**

**d.** Only PDF files are allowed.

**ordemDocumento**\
When more than one file is being sent in the process, it is necessary to define the order in which these files will be listed for the signer to sign. This order will also be used to relate the signer's signature placement in the respective file. See the parameter documentoDeOrdem.

**a.** For a process with more than one file, the ordemDocumento parameter is mandatory in each document.

**b.** Files with the same order are not allowed.

**c.** When more than one file is sent, they will be considered as a collection of files for the process in question; they **will not be merged**, i.e., grouped into a single file. It is not possible to group files through the document signing process service.

**nomeComExtensao**\
Mandatory parameter to inform the file name with its extension, allowing up to 150 characters.

**a.** The application does not allow files with the same name in a single process.

**arquivo**\
Mandatory parameter to inform the PDF file in base64 format.

**a.** It is mandatory to send at least one file. It must be sent in PDF format.

## Return Validations

### **Error: 400 - Bad Request**

This error is returned when the request cannot be interpreted and/or the server attempts to process the request, but some parameter in the request is invalid, such as a resource formatted incorrectly or an attempt to request with missing data. Information about the request is provided in the body of the response and includes an error code and an error message.

**a. Mandatory Item:** This message is displayed in singular or plural when one or more mandatory items have not been sent in the API call.

**The listed item(s) is/are mandatory: “names of the items separated by commas.”**

**b. Incorrect Format:** This message is displayed in singular or plural when one or more items have been sent with an incorrect format.

**The listed item(s) are in the incorrect format: “names of the items separated by commas.”**

**c. Nonexistent IDs:** This message is displayed in singular or plural when one or more IDs sent do not exist.

**The listed ID(s) do not exist: “names of items that are table IDs, separated by commas.”**

**d. Some parameter is incorrect or nonexistent:** This message is displayed when the call is made with some parameter written incorrectly or when an information that does not exist in the method is sent.

**Some parameter is incorrect or nonexistent.**

### Error: 401 - Unauthorized

This error is returned when:

* The ArqSign API authentication key is incorrect or was not provided correctly.
* The account is in a status other than Active.

### Error: 404 - Not Found

This error is returned when the requested resource or endpoint was not found.

### Error: 422 - Unprocessable

This error is returned when the request was successfully received, but contains invalid parameters.

### Error: 500 - Server Error

This error is returned when:

* An internal server error occurs.
* A failure occurs on the ArqSign platform.
* Incorrect parameter format.
* Incorrect JSON format.

## Success Return

When the process is successfully sent, the system returns the process ID and the document ID(s) of the process.

Code 200 – OK
