# ✔️ 1.4. GET /api/v1/processo/{idProcesso}/status-do-processo

Objective The purpose of this method is to allow the user to check the status of a signature process, avoiding the need to fetch the entire process using the method “GET /api/v1/processo/{idprocesso}” before it has the status “Completed.”

In this method, the user will send us the Process ID, and we will return a JSON with its name and current status.

## Request

<figure><img src="../../../.gitbook/assets/image (218).png" alt=""><figcaption></figcaption></figure>

### Detalhamento do Header e Parameters

**Ref. 01:** “AppKey” is the authorization key to authenticate in the API. This key must be valid and linked to an active ArqSign account.

**Ref. 02:** “idProcesso” - To retrieve the status of the process, the Process ID must be sent as a parameter. This ID is returned by the API after a successful call to the method: **POST /api/v1/processo/enviar-documento-para-assinar.**

## Return

<figure><img src="../../../.gitbook/assets/image (219).png" alt=""><figcaption></figcaption></figure>

### Return Details

**Ref. 01 - Code 201:** As a successful response, the application will return the code 201 along with the name and status of the process.

Process Status:

1. Created
2. Pending
3. In Process
4. Completed
5. Canceled

{% hint style="success" %}
The service **"/api/v1/processo/{idprocesso}"** returns the process data, and in the object **"signatarios.dadosAssinatura"**, there is information about the signature of each signatory.

If the value is **"null"**, it means the signatory has not signed yet.\
<mark style="color:red;">**Null = Pending**</mark>

If there is signature data, it means the signatory has signed.\
**Presence of data = Signed**
{% endhint %}

**Ref. 02 - Code 400:** Message of Required Item: This message will be displayed in singular or plural when one or more required items have not been sent in the API call.

**Ref. 03 - Code 400:** Message of Incorrect Format: This message will be displayed in singular or plural when one or more items have been sent with an incorrect format.

**Ref. 04 - Code 400:** Message of Nonexistent IDs: This message will be displayed in singular or plural when one or more IDs sent do not exist.

**Ref. 05 - Code 400:** Message of Deleted Document: This message will be displayed when the process in question has been logically deleted.

**Ref. 06 - Code 400:** Message of Incorrect or Nonexistent Parameter: This message will be displayed when the API call contains a parameter written incorrectly or a parameter that does not exist in the method.

**Ref. 07 - Code 401:** Message of Unauthorized API User: Invalid or not found AppKey.
