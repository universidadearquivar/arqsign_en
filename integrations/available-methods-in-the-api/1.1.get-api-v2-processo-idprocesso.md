## Authentications and Validations

1. To authenticate on the ArqSign API, the user must provide the valid AppKey of the account they are using to retrieve the process.
2. Only accounts with an **Active status** and **integration permissions for ArqSign** can retrieve processes via the ArqSign integration.
3. It is mandatory to provide the IdProcesso for the process data query.
4. The system validates if the **IdProcesso** belongs to the account of the provided **AppKey**.

## Return Validations

### Error: 400 - Bad Request

This error is returned when the request cannot be interpreted and/or the server attempts to process the request, but one of the parameters in the request is invalid, such as an incorrectly formatted resource or a request with missing data. Information about the request is provided in the response body and includes an error code and an error message.

**a. Mandatory Item:** This message is shown in singular or plural when one or more mandatory items were not sent in the API call.

**Message: The listed item(s) is/are mandatory: “name of items separated by a comma.”**

**b. Incorrect Format:** This message is shown in singular or plural when one or more items were sent in the wrong format.

**Message: The listed item(s) have the incorrect format: “name of items separated by a comma.”**

**c. Nonexistent Ids:** This message is shown in singular or plural when one or more sent Ids do not exist.

**Message: The listed Id(s) do not exist: “name of items that are table Ids, separated by a comma.”**

**d. Deleted Document:** This message is displayed when the document is found to be deleted.

**Message: Document deleted.**

**e. Incorrect or Nonexistent Parameter:** This message is displayed when the call is made with a parameter written incorrectly or when a non-existent information is sent for the method.

**Message: Some parameter is incorrect or nonexistent.**

### Error: 401 - Unauthorized

This error is returned when the authentication key for the ArqSign API is incorrect or was not properly provided.

### Error: 404 - Not Found

This error is returned when the requested resource or endpoint was not found.

### Error: 422 - Unprocessable

This error is returned when the request was successfully received, but contains invalid parameters.

### Error: 500 - Server Error

This error is returned when:

* An internal server error occurs.
* A failure occurs in the ArqSign platform.
* The JSON format is incorrect.

## Success Response

Status 200 - Success

The system returns the process data, signatory data, process file, and signature record.

* Process Data
* Signatory Data
* Process Documents with their respective signature records.

## Process Data

This part of the JSON returns the data of the signature process.

**nomeProcesso**

The system returns the name of the process.

**idPasta**

The system returns the ID of the process folder.

**caminhoDaPasta**

The system returns the path of the process folder.\
Example: Archive \Administration \ Contracts

**idResponsavel**

The system returns the ID of the responsible person (sender) of the process.

**nomeResponsavel**

The system returns the name of the responsible person for the process.

**status**

The system returns the status of the process **(Created, Awaiting, In Process, Completed, or Canceled).**

**dataCadastro**

The system returns the registration date of the process.

**dataEnvio**

The system returns the sending date of the process. The process will have a sending date (**dataEnvio**) when the status is different from **Created.**

**dataConclusao**

The system returns the completion date of the process. The process will have a completion date (**dataConclusao**) when the status is equal to **Completed.**

**dataRenovacao**

The system returns the renewal date of the process. The process will have a renewal date (**dataRenovacao**) when there is a renewal configuration and the document is in **Completed** status.

The system should calculate the renewal date based on the renewal configuration and the document's completion date. (**dataRenovacao = dataConclusao + renovacaoMeses**).

**dataCancelamento**

The system returns the cancellation date of the process. The process will have a cancellation date (**dataCancelamento**) when the status is equal to Canceled.

**usuarioCancelamento**

The system returns the name of the user who canceled the process. The document will have the name of the user who canceled the document (**usuarioCancelamento**) when there is a cancellation date (**dataCancelamento**) and the status is equal to Canceled.

**dataReenvio**

The system returns the resending date of the process. The process will have a resending date when the sender resends the process to the signatories pending signatures.

**dataExpiracao**

The system returns the expiration date of the process.

The system should calculate the expiration date based on the configuration and the sending/resending date of the document.\
If **dataReenvio** is null, then **dataExpiracao = dataEnvio + ExpiracaoDias.**\
If **dataReenvio** is not null, then **dataExpiracao = dataReenvio + expiracaoDias.**

**expiracaoDias**

The system returns the expiration days of the process.

**avisoExpiracaoDias**

The system returns the days for the expiration warning of the process.

**lembrete**

The system returns the data indicating whether the process has a reminder for signing.

The parameter (**lembrete**) indicates whether the process has a reminder for signing or not.\
1 - true = has a signing reminder.\
0 - false = does not have a signing reminder.

**frequenciaLembrete**

The system returns the frequency of the signing reminder for the document(s) of the process.

## Signer Data

This part of the JSON returns the data of the signatories participating in the signature process.

**signatarios**

**ordemAssinatura**

The system returns the signing order of the signatory in question.

**id**

The system returns the ID of the recipient process.

**nome**

The system returns the name of the signatory.

**email**

The system returns the signatory's email when the process was sent by **email.**

**telefone**

The system returns the signatory's phone number when the process was sent via **WhatsApp**.

**aguardandoEnvio**

The system returns information about whether the process is awaiting sending, which can be true or false. This parameter will be true when the signature process has a signing order and the previous signatory has not completed their signature, so the signatory is waiting for the document to be sent for signing.

**falhaEnvio**

The system returns information about a failure in sending the process, which can be true or false. This parameter will be true when there is a failure in sending the process to the recipient.

**tipoAcao**\
The system returns the type of action the signatory will take in the process, which can be "**Sign Online**" or "**Receive a Copy**."

**copiaEnviada**

The system returns information about whether a copy has been sent when the signatory has the action of "**Receive a Copy**." This parameter will be true if a copy was sent or false if it was not sent.

**remetente**

The system returns information about whether the signatory is also the sender of the process. This parameter will be true if the signatory is the sender or false if the signatory is not the sender.\
Note: The sender of the process may also participate as a signatory.

**assinaturaRecusada**

The system returns information about whether the signature was refused by the signatory. This parameter will be true if the signatory refused to sign the document(s) or false if the signatory did not refuse the signature(s).

**motivoRecusa**

The system returns the reason for refusal if the signatory refused to sign the document(s). When the **assinaturaRecusada** parameter is **true**, the **motivoRecusa** parameter must contain the reason for refusal as provided by the signatory, and the status of the process should be "**Canceled.**"

**seguranca**

The system returns security data only if the signatory has these configurations to access the document(s) of the process.

* **codigoSeguranca**                                                                                                                                             The system returns the security code generated when the process was sent for signatures.
* **codigoSegurancaEmail**                                                                                                                                            The system returns the email when the security code was sent by **email.**
* **codigoSegurancaTelefone**                                                                                                                                          The system returns the phone number when the security code was sent via **WhatsApp** or **SMS**.

**papelSignatario**&#x20;

The system returns the role(s) of the signatory only if the signatory has these configurations.

* **pessoaFisica**

The system returns this information when the signatory has a role as an individual.

* **pessoaJuridica**

The system returns this information when the signatory has a role as a legal entity.

**dadosAssinatura**

The system returns signature data of the signatory.

* **tipoAssinatura**

The system returns the type of signature the signatory executed or will execute. This parameter can be: "**Electronic Signature,**" "**Digital Certificate – ICP Brazil,**" or "**Digital Certificate – Others.**"\
When the signatory's **action type** is "**Receive a Copy**," the tipoAssinatura parameter will be **null**.

* **dataAssinatura**

The system returns the date the signatory signed the document. This parameter will be null if the signatory has not signed the document(s).

* **ip**

The system returns the IP of the signatory who signed the document. This parameter will be null if the signatory did not sign the document(s).

* **geoLocalizacao**

The system returns the geolocation of the signatory who signed the document. This parameter will be null if the signatory did not sign the document(s) or if the signatory did not allow the location to be captured.

* **dadosCertificado**

The system returns the certificate data used for signing the document(s). These parameters will be null if the signatory did not sign the document(s).

* **nome**

The system returns the name of the certificate.

* **emissor**

The system returns the issuer of the certificate.

* **validadeInicio**

The system returns the start of the certificate validity.

* **validadeFim**

The system returns the end of the certificate validity.

**dadosPessoaFisica**

These data will be returned when signatories with electronic signatures provide their personal data. These parameters will be null when:

* The signature type is with a digital certificate (ICP-Brazil or Others), or
* The signatory did not provide personal data for the electronic signature, or
* The signatory did not sign the document(s).

**nomePessoaFisica**

The system returns the name provided by the signatory when signing the document(s).

**tipoDocumentoPessoaFisica**

The system returns the type of personal document of the signatory. This can be **CPF, CNH, RG**, or **Other**. When the type is **Other**, the system will display the name of the document type defined by the user/sender.

**numeroDocumetoPessoaFisica**

The system returns the number of the personal document provided by the signatory when signing the document(s).

**dadosPessoaJuridica**

These data will be returned when signatories with electronic signatures provide their legal entity data. These parameters will be null when:

* The signature type is with a digital certificate (ICP-Brazil or Others), or
* The signatory did not provide legal entity data for the electronic signature, or
* The signatory did not sign the document(s).

**nomeEmpresa**

The system returns the name of the company provided by the signatory.

**tipoDocumentoEmpresa**

The system returns the type of legal entity document provided by the signatory when signing the document(s). This can be **CNPJ or Other**. When the type is **Other**, the system will display the name of the document type defined by the user.

**numeroDocumentoEmpresa**

The system returns the number of the company document provided by the signatory when signing the document(s).

**anexos**

The system returns attachment data when the signatory uploads attachments, according to the process configuration. These parameters will be null when there are no attachments for the signatory.

* **id**

The system returns the ID of the attachment uploaded by the signatory.

* **anexoDocumentoNome**

The system returns the name of the attachment from the signatory.

### Process Document Data

A signature process may contain one or more documents to be signed.

**documentos**

The system returns the document(s) of the signature process in the order defined by the ordemDocumento parameter, with their respective signature records.

**id**

The system returns the ID of the document in question.

**ordemDocumento**

The system returns the order of the document defined when the process was sent.

**nomeDocumento**

The system returns the name of the document.

**base64Documento**

The system returns the base64 of the document file.

**registroAssinaturas**

The system returns the signature record for each document of the process.

* **nome**

The system returns the name of the signature record. The name of the signature record must include the document name followed by the string "\_registro de assinaturas."\
Example: Rental Agreement\_Registro de assinaturas.pdf

* **base64**&#x20;

The system returns the base64 of the signature record file.
