# ✔️ 1.1. POST/api/v2/processo/enviar-documento-para-assinar

The purpose of this method is to allow clients, via API, to send processes containing one or more documents for signature.

Unlike the ArqSign application, which enables grouping files within a process, this service treats multiple documents **in a process as a collection of files**. These files will not be grouped into a single document. In other words, file grouping is not possible through the document signature process submission service.

The user must provide the process details and the participants' information for the signing process.

## Authentication and Permissions

1. To authenticate with the ArqSign API, the user must provide a valid AppKey associated with the account sending the documents for signatures.
2. Only accounts with **Active status** and **ArqSign Integration permissions** can submit processes via the ArqSign integration.
3. The account must have sufficient credits for Submissions, SMS, and/or WhatsApp, depending on the requirements.
4. If the account lacks credits, the system will return the message: _"Insufficient credits for Submissions, WhatsApp, or SMS."_

## Request: Parameters

**Guidelines:**

When the "Required" field is marked as "Yes" = Always required.

When the "Required" field is marked as "No" = Optional information.

When the "Required" field is marked as "Maybe" = Required in certain cases. Refer to the topic description according to the row reference number in the table.

When the "Required" field is marked as "No" = Optional information.

## Description of JSON Parameters

### idResponsavel

**Mandatory** parameter specifying the ID of the process owner. This information will be considered the owner responsible for the registration and the process, i.e., the "sender" of the process. Thus, if the specified user logs into the application, they will see all documents in the "Enviados" menu.

You must provide the ID of an active user belonging to the account.

### nomeProcesso

Mandatory parameter specifying the name of the process, allowing up to 250 characters.

### idPasta

Mandatory parameter specifying the folder ID of the process. You must provide the ID of a folder belonging to the account.

### configuracoesAvancada

In this section of the JSON, the user can send advanced settings for the process, including expiration time, expiration warning, frequency of this warning, QRCode generation, and document reading requirement for the process.

Advanced settings are **optional**. **If not sent** or sent as null, the system **saves the process with the account's default settings**.

### tempoExpiracaoDocumentoDias

**Optional** parameter specifying the time the process will be available for signature until all signers sign and the process is completed.\
Allowed values range from {1} to {999}.

If this parameter is not sent, sent as null, or set to 0, the system uses the account's default settings.

### avisoAntesExpiracaoDocumentoDias

**Optional** parameter specifying the time for the application to start warning before the document expires.\
Allowed values range from {1} to {99}.

If this parameter is not sent, sent as null, or set to 0, the system uses the account's default settings.

### frequenciaLembretesDias

**Optional** parameter specifying the frequency of signature reminders.\
Allowed values range from {1} to {999}.

If this parameter is not sent, sent as null, or set to 0, the system uses the account's default settings.

### gerarQrCode

**Optional** parameter specifying whether to generate the QRCode for the signed document upon process completion.\
If the process includes more than one document for signature, the QRCode will be generated per document. Each document will have its QRCode and signature page.

Allowed values: 1 = true or 0 = false.

If this parameter is not sent, sent as null, or set to 0, the system uses the account's default settings.

### obrigarLeitura

**Optional** parameter specifying whether document reading is mandatory before signing.\
If the process includes more than one document to sign, this information will determine whether the signer is required to click on each document before the "Assinar" button is enabled.\
If the process has only one file to sign, this information is not necessary for the signing process.

Allowed values: 1 = true or 0 = false.

If this parameter is not sent, sent as null, or set to 0, the system uses the account's default settings.

### renovacaoMeses

**Optional** parameter specifying the renewal period, in months, for the process in question.

### mensagemPadrao

**Optional** parameter specifying the default message to be sent to all recipients designated as signers of the process.\
If the **“mensagemPadrao” data collection is not sent**, the system sends notifications with default values:\
**Title** = ArqSign: \[Document name provided in the "nome" parameter]\
**Text** = You have received the document(s): \[Document name provided in the "nome" parameter] for signatures.

**Title**\
**Optional** parameter specifying the title of the message to be sent to the signers.

**text**\
**Optional** parameter specifying the text of the message to be sent to the signers.

### usarOrdemAssinatura

Mandatory parameter indicating whether or not the order of signature will be used for the signers.\
Allowed values: 1 = true or 0 = false.

a. When the **usarOrdemAssinatura** parameter is sent as false, the system disregards the value specified in the **ordemAssinatura** parameter for all recipients with the "Assinar Online" action and sends the process to all recipients, treating them as order 1.

b. When the **usarOrdemAssinatura** parameter is sent as true, the system validates the **ordemAssinatura** parameter for all recipients with the "Assinar Online" action. In this case, the **ordemAssinatura** parameter for the recipients cannot be zero or null.

If the process has a signing order, the system sends the process only to recipients with order 1.

### usarPosicaoAssinaturaAutomatica
